01 · Boundary

Local versus remote: the offline scan only sees this side of the line

Every harness also talks to its vendor. Those prompts, cloud sessions and server-side histories live above the boundary, and no collector in aiscan all reaches them. Select a store to jump to its atlas entry.

Local, read by aiscan

Config files, permission lists, MCP registries, session JSONL, SQLite state, app-data folders and git repositories on this machine. Some are parsed, some only stat'ed.

Remote, not read

Vendor-side conversation storage, cloud sessions and tasks, synced histories, admin policy held in the cloud. A local scan cannot prove what is or is not stored there.

Remote, opt-in only

aiscan cloud-agents lists Cursor Cloud Agents through the official API with your key. tools/github-access is a separate script with its own token.

02 · Architecture

collectors → normalized evidence → analysis → briefing, as the code actually does it

The shorthand is close, with one correction: most analysis happens inside each collector. Collectors read files and assign severity themselves. Later steps never go back to the machine; they only read envelopes.

01 Launch aiscan.ps1

One PowerShell entry point. all (the default) runs twelve offline collectors in a fixed order. cloud-agents and telemetry are separate commands; discover and summary are modes.

Inputs
Command name and flags: -OutDir / -Here, -Briefing, -Redact, -RepoRoots, -AgentMode, -LaunchedBy, -Reason.
Outputs
A scan root with evidence\ and raw\, plus run-origin.txt. Without -OutDir or -Here the root is %TEMP%\aiscan-<stamp>-<nonce>, deleted at the end unless -Keep or -Briefing is set.
Reading the source
The component.json in_all flags agree with the list, but aiscan.ps1 does not read them: the order is hard-coded.

02 Resolve paths core/paths.py

Each tool home is resolved once with precedence CLI flag > paths.json > tool env var > default, and passed to collectors as flags.

Inputs
CLAUDE_CONFIG_DIR, CODEX_HOME, GROK_HOME, optional paths.json; defaults under %USERPROFILE% and %APPDATA%.
Outputs
Process arguments only. Evidence stores a hashed path_id and a source label, never the resolved path.
Reading the source
discover prints what would be scanned without reading content.

03 Collect components/*

Each collector reads its tool's files read-only and decides findings and rules itself. Severity is assigned here, not in a later analysis stage.

Inputs
Harness config, session stores, SQLite state (read-only, or a temp copy for accounts), repos.
Outputs
One envelope per collector; chat-history, secrets-scan and pii-scan also write raw\.
Reading the source
This is where 'analysis' mostly happens: collectors are both readers and rule engines.

06 Derive agent-summary, scan_diff, access map

Derived steps read envelopes only, never the machine. agent_summary.py writes a safe summary every scan; run_status.py turns exit codes into the scan exit code; with -Briefing, scan_diff.py writes changes.json against a previous scan; the access map is computed while the briefing renders.

Inputs
evidence\*.json, run-origin.txt.
Outputs
agent-summary.json, run-status.json, changes.json (with -Briefing).
Reading the source
The access map is pure: it never touches the filesystem and leaves uncaptured cells unknown.

09 · Limitations

Limits of this atlas

  • Source facts are pinned to one commit. A later commit can change any path, mode or default shown here; re-run python docs/atlas/build_atlas.py --verify after rebasing.
  • 'What the harness keeps' is drawn from aiscan's own code comments and from the public vendor pages listed in the manifest, read on the date shown. Vendors change storage layouts and retention without notice.
  • Grok Build and Grok Bot remote storage were not verified from public documentation. Grok Bot statements come from repository source comments.
  • 'Not read' means no collector source in this commit references the location. It is a statement about aiscan, not proof that the location exists on every install.
  • The overlap where chat-history exports JSONL from the whole %APPDATA%\Claude tree is read from the code path, not observed on a machine.
  • No real machine was scanned to make this page. Example paths are generic placeholders.
  • This page explains coverage; it is not a security assessment of any vendor.
